# LOTO / SWP Toolkit

A web app for running Safe Work Permits (SWP) and Lockout/Tagout (LOTO) at an industrial site.
It replaces paper permits and spreadsheets with one system: crews fill permits on a phone or
laptop, the right people get asked to sign, and every finished permit prints on the site's
standard form.

**Flask · SQLite · HTMX** — server-rendered, almost no JavaScript, runs in one container.

## What it does

- **Safe Work Permits**: permit info, pre-job questions, hazardous energy, task hazard
  assessment, PPE, task safeguards, associated permits, attendees. Lifecycle `draft → issued → closed`.
- **Lockout/Tagout permits**: isolation boundaries (device, equipment, position), verifier
  sign-off, lifecycle `draft → submitted → active → released`. Can be linked to an SWP.
- **Combined SWP + LOTO form** for jobs that need both, filled once.
- **Continuation sheets**: PJSM continuation and work continuation addenda on an open SWP.
- **Signature requests**: work leads and authorizers get a one-time, expiring link (SMS via
  Twilio when configured) and sign from their own device.
- **Equipment registry** with a search-as-you-type picker, so isolation points are named the
  same way every time.
- **Contractor roster** for attendee and work-lead fields.
- **PDF export and printing**: permits fill a fillable PDF / Excel template, are flattened
  with Ghostscript or converted with LibreOffice, and can be sent straight to a CUPS printer.
- **Historical entry**: old paper permits can be back-entered; they're closed and tagged.
- **Autosave** on every form, so a dropped connection in the field doesn't lose work.
- **Roles**: `it_admin`, `admin`, `operator`, `mechanic`, `ei_c`, `user`.
- **Audit log** of every login, permit change, signature and user change, with CSV export.
- **CLI** to create permits and load equipment from JSON (`flask create-swp`, `create-loto`,
  `add-equipment`).

## Security

| Area | Implementation |
|---|---|
| Passwords | Argon2id; new accounts get a random temporary password shown once and must change it on first login |
| Sessions | `HttpOnly`, `SameSite=Lax`, `Secure` in production |
| CSRF | Flask-WTF on every form and HTMX request |
| Login | Rate limited (Flask-Limiter); open-redirect check on `next` |
| Access control | Role decorator on every route; ownership checks against IDOR |
| Headers | CSP (`script-src 'self'`), `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy` |
| Container | Non-root user, read-only filesystem, all capabilities dropped, memory/CPU limits |

The `tests/security/` suite covers access control, CSRF, headers, IDOR, injection, password
handling, rate limiting and sessions.

## Quick start

Requires Python 3.11+, plus Ghostscript and LibreOffice for PDF export.

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
python scripts/create_user.py   # create the first it_admin
python run.py                   # http://127.0.0.1:5000
```

Run the tests:

```bash
pytest
```

## Configuration

| Variable | Purpose |
|---|---|
| `SECRET_KEY` | Flask secret. Generated into `instance/secret_key` if unset. |
| `COMPANY_NAME` | Pre-fills the Company field on new permits. |
| `FLASK_ENV` | `production` turns on secure cookies and HTTPS URLs. |
| `PRINTER_NAME`, `CUPS_SERVER` | CUPS queue for the Print button. Leave empty to disable. |
| `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_FROM_NUMBER` | SMS for signature requests. Optional. |

## Using your own forms

`forms/` holds the templates the export fills: `swp/swp-form.pdf` (fillable PDF) and
`loto/loto-form.xlsx`. Both are generated by `tools/make_templates.py`. To print on a site's
own paperwork, replace them with your forms, keeping the PDF field names (they match the
`swp_permits` columns) and the workbook cell addresses used in `app/pdf.py`.
